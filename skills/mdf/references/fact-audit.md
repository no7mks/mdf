# Fact Audit

## 决策树

```text
┌──────────────────────────────────┐
│ 1 Resolve scope                  │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [停止]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 2 Audit CLI                      │
└────────────────┬─────────────────┘
                 │
                 ├──── init 且仅 initializing ────→ 3 Review facts
                 ├──── 其他失败或缺失 ────────────→ [停止]
                 │
                 ▼ CLI 成功
┌──────────────────────────────────┐
│ 3 Review facts                   │
└────────────────┬─────────────────┘
                 │
                 ├──── 无法完成复核 ────→ [停止]
                 │
                 ▼ 通过（含已记录发现）
┌──────────────────────────────────┐
│ 4 Review coverage                │
└────────────────┬─────────────────┘
                 │
                 ├──── 无法完成复核 ────→ [停止]
                 │
                 ▼ 通过（含已记录发现）
┌──────────────────────────────────┐
│ 5 Review warnings                │
└────────────────┬─────────────────┘
                 │
                 ├──── 无法完成审阅 ────→ [停止]
                 │
                 ▼ 通过（含未确认项记录）
┌──────────────────────────────────┐
│ 6 Validate                       │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [停止]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 7 Confirm review                 │
└────────────────┬─────────────────┘
                 │
                 ├──── 通过 ────────────────→ [审阅通过]
                 ├──── 未通过且独立调用 ────→ [报告未通过并结束]
                 └──── 未通过且内部委托 ────→ [返回未通过，调用方走失败分支]
```

## 工作流（唯一执行契约）

表中操作与证据按下方同名条目核对；顺序与跳转只由本表规定。

完整读取 `references/common.md` 与 `references/repository-contract.md`。

| # | 步骤 | 类型 | 做什么 | 证据 | 通过 → | 失败/缺失 → |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 范围 | 约束 | 确认调用方、状态及文档/实现审阅范围 | 类型、两类范围 | 2 | 停止 |
| 2 | 映射 | 脚本 | 按精确范围运行 fact-audit CLI | 映射、findings | 3 | init 仅 initializing 则 3；其他停止 |
| 3 | 事实 | 约束 | 逐份核对当前事实陈述及 evidence 与实现 | 事实复核、语义发现 | 4 | 无法复核则停止 |
| 4 | 覆盖 | 约束 | 从实现反查产品与系统各面的文档覆盖 | 覆盖、遗漏与错误 | 5 | 无法复核则停止 |
| 5 | 警告 | 约束 | 逐条审阅未引用实现的 warning 并确认 | 逐条用户确认 | 6 | 无法审阅则停止 |
| 6 | 校验 | 脚本 | 运行 `validate --scope full`，不运行验证命令 | validation findings | 7 | 停止 |
| 7 | 确认 | 约束 | 报告发现并取得当场确认 | 摘要、当场确认 | 审阅通过 | 报告未通过；独立结束，委托返回 |

## 术语与数据结构

### 范围与确定性映射

<a id="s1"></a>

**范围**

它只读：不写入、移动、提交、生成持久报告或执行 `verification.commands`。

确定类型和状态：fact update 委托时使用其明确范围，允许审阅调用方的同次写入；
direct 执行`全量审阅`、manifest 必须 `ready`；init 为全量、允许 `initializing`；
finish 的 release 为全量，其他分支为调用方给出实现和当前事实文档范围的范围审阅。
审阅不要求 clean，不替调用方提交；未提交内容仍须满足 evidence 与 full validation 契约。

验收：调用方与范围。

<a id="s2"></a>

**映射**

调用 `fact-audit` CLI；全量不带路径，范围使用调用方计算的精确路径。

验收：范围、文档—`evidence` 映射、ignore 匹配、warnings、确定性 findings。

通过条件：CLI 成功，或 init 调用时返回结构化结果且 findings 仅有
`manifest.initializing`；后一种即使退出码为 2、ok 为 false 也继续审阅。
异常与交接：其他调用失败或确定性 finding 时停止；不得把解析失败当作初始化豁免。

### 双向复核与确认

<a id="s3"></a>

**事实**

从文档到实现执行`事实复核`：复核范围内每份当前事实文档、陈述和 `evidence`。
范围内未复核的文档逐份记录未触及理由，供步骤 7 报告。

验收：事实复核、未触及理由。

异常与交接：记录语义 finding 后继续 4。

<a id="s4"></a>

**覆盖**

从实现到文档复核产品行为、系统边界、架构、接口、数据与运维实现。

验收：未记录实现、过时/错误陈述、不可验证 evidence 与计划混写 findings。

异常与交接：记录语义 finding 后继续 5。

<a id="s5"></a>

**警告**

逐条审阅 CLI warning。

验收：未被 evidence 引用且未被 ignorelist 覆盖的实现文件及用户当场确认。

异常与交接：列入会话摘要后继续 6。

<a id="s6"></a>

**校验**

运行 `validate --repo "$REPO_ROOT" --scope full`（即 full validation），不运行验证命令；
init 只允许 `manifest.initializing` finding。

验收：validation findings。

异常与交接：报告并停止。

<a id="s7"></a>

**确认**

返回审阅类型、两类范围、映射、warnings、复核文档、语义/validation findings 与未触及理由。

验收：会话摘要和用户当场确认。

通过条件：无语义 finding、无未确认 warning，且 validation 无阻断 finding 时通过；init 仅豁免
`manifest.initializing`。该确认不跨调用复用。

异常与交接：存在其他 finding、未确认 warning 或未取得用户确认时，报告审阅未通过、
阻断原因与待确认项，不得称审阅通过。独立调用报告后结束；内部委托返回未通过结果，
由调用方进入既有失败分支，不得推进依赖审阅通过的步骤。修复、补充确认或重审由调用方
按其契约处理；fact audit 保持只读，不自行修复或自动重试。

Audit 不检查 Gitflow 分支、变更 diff、Proposal、Bug、Change、release 输入、closeout 或 merge 条件；这些属于
`$mdf finish` 的交付前检查。

### 审阅类型

- `全量审阅`：从文档和实现两个方向覆盖全部当前事实文档与实现面。
- `范围审阅`：从文档和实现两个方向覆盖调用方给定的实现与文档范围。
