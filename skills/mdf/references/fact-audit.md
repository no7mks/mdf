## 术语与数据结构

### 执行约束

下列明细补充表中操作、证据与异常处理；步骤顺序和跳转只由上表规定。

<a id="s1"></a>

**范围**

确定类型和状态：fact update 委托时使用其明确范围，允许同次写入且不重查 clean；
direct 执行`全量审阅`、manifest 必须 `ready` 且查 clean；
 init 为全量、允许 `initializing`
且不重查 clean；finish 的 release 为全量， 其他分支为调用方给出实现和当前事实文档范围的范围审阅。

验收：调用方与范围。

<a id="s2"></a>

**映射**

调用 `fact-audit` CLI；全量不带路径，范围使用调用方计算的精确路径。

验收：范围、文档—`evidence` 映射、ignore 匹配、warnings、确定性 findings。

异常与交接：调用失败或有确定性 finding 时停止。

<a id="s3"></a>

**事实**

从文档到实现执行`事实复核`：复核范围内每份当前事实文档、陈述和 `evidence`。

验收：事实复核。

异常与交接：记录语义 finding 后继续 4。

<a id="s4"></a>

**覆盖**

从实现到文档复核产品行为、系统边界、架构、接口、数据与运维实现。

验收：未记录实现、过时/错误陈述、不可验证 evidence 与计划混写 findings。

异常与交接：记录语义 finding 后继续 5。

<a id="s5"></a>

**警告**

逐条审阅 CLI warning。

验收：未被 evidence 引用且未被 ignorelist 覆盖的实现文件及用户当场确认。

异常与交接：列入会话摘要后继续 6。

<a id="s6"></a>

**校验**

运行 `full validation`，不运行验证命令；init 只允许 `manifest.initializing` finding。

验收：validation findings。

异常与交接：报告并停止。

<a id="s7"></a>

**确认**

返回审阅类型、两类范围、映射、warnings、复核文档、语义/validation findings 与未触及理由。

验收：会话摘要和用户当场确认。

通过条件：无语义 finding、 无未确认 warning，且 validation 无 finding 时通过。异常与交接： init 仅豁免
`manifest.initializing`，不得将其计为阻断 finding；不得称审阅通过。该确认不跨调用复用。
Audit 不检查 Gitflow 分支、变更 diff、Proposal、Bug、Change、release 输入、closeout 或 merge 条件；这些属于
`$mdf finish` 的交付前检查。

### 审阅类型

- `全量审阅`：从文档和实现两个方向覆盖全部当前事实文档与实现面。 - `范围审阅`：
从文档和实现两个方向覆盖调用方给定的实现与文档范围。
