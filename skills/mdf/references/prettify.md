# Prettify

## 决策树

```text
┌──────────────────────────────────┐
│ 1 Resolve scope                  │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [停止并报告]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 2 Check                          │
└────────────────┬─────────────────┘
                 │
                 ├──── 无违例且无需改写 ────→ [结束]
                 ├──── 失败/缺失 ───────────→ [停止并报告]
                 │
                 ▼ 有待改写文档
┌──────────────────────────────────┐
│ 3 Rewrite                        │
└────────────────┬─────────────────┘
                 │
                 ├──── 语义不明 ────→ [停止并询问]
                 │
                 ▼ 已改写
┌──────────────────────────────────┐
│ 4 Verify                         │
└────────────────┬─────────────────┘
                 │
                 ├──── 仍有违例或语义丢失 ────→ 3 Rewrite
                 ├──── 其他失败 ──────────────→ [停止并报告]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 5 Record                         │
└────────────────┬─────────────────┘
                 │
                 ├──── 通过 ─────────→ [结束]
                 └──── 失败/缺失 ────→ [停止并报告]
```

## 工作流（唯一执行契约）

读取 `references/common.md` 与 `references/doc-structure.md`。

| # | 步骤 | 类型 | 做什么 | 证据 | 通过 → | 失败/缺失 → |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Resolve scope | 约束 | 解析目标根、写入分支与待美化文档 | 目标根、分支、文档清单 | 2 | 停止并报告 |
| 2 | Check | 脚本 | 运行 prose-check，逐份审软限制与形态 | 违例清单、审阅发现 | 有待改写 3；否则结束 | 停止并报告 |
| 3 | Rewrite | 约束 | 逐份结构化改写，不改语义 | 改写后的文档 | 4 | 语义不明则停止询问 |
| 4 | Verify | 脚本 | 复跑 prose-check 与 validate，对照语义 | 零违例、零 finding、语义对照 | 5 | 可修回 3；否则停止 |
| 5 | Record | 约束 | 提交本次改写并报告 | 提交、改写清单 | 结束 | 停止并报告 |

`$mdf prettify [<path>...] [--scope branch|full|paths]` 执行本流程。

## 术语与数据结构

### 范围与分支

本节确定改哪些文档、在哪个分支上改。

| 调用 | 待美化文档 |
| --- | --- |
| `--scope full` | 全部带角色文档（`docs/JOTS.md` 除外） |
| `--scope branch`（默认） | 当前分支相对起点改动过的带角色文档 |
| `<path>...` 或 `--scope paths` | 所列仓库内 Markdown 文件 |

- 写入分支遵守 `common.md` 的写入规则。
  - ❌ 不在 master 上直接改写。
  - 与当前交付相关的文档在该交付分支改写；其余在 develop 或 planning 按公共规则处理。
- ✅ 可改：根文档、`docs/**`、`AGENTS.md` 托管区块。
- ❌ 不改：`docs/JOTS.md`、`docs/repowiki/`、代码块内容、frontmatter 键、`{{MDF_...}}` 槽位。

### 检查与改写

先用 CLI 列出硬限制违例，再按审阅规则找出需要结构化的段落。

- 运行 `python3 "$MDF_ROOT/scripts/mdf.py" prose-check --repo "$REPO_ROOT"`，
  按范围逐个附加 `--path`。
- 硬限制之外，逐份按 `doc-structure.md` 的软限制与内容形态审阅。
- 改写手段按内容选择：

| 原文形态 | 改写为 |
| --- | --- |
| 大段说明 | 一句概述加列表 |
| 并列多项 | 列表或多级列表 |
| 条件分支 | 表格或决策树 |
| 有序流程 | 编号列表或图 |
| 对象与属性 | 表格 |
| 易错点、禁止项 | ⚠️、❌ 行首标记 |

- 📌 只改结构，不改语义：
  - 每条规则、条件、例外、数值、路径、命令与链接都要保留。
  - 不新增事实，不改变措辞的强度（必须、可以、不得）。
  - 标题与 `<a id>` 锚点保持可被原有链接命中。
- 语义有歧义、改写须取舍内容时停止询问，不自行裁定。

### 复核与记录

改写后用确定性检查与逐份对照两层确认。

- 复跑 `prose-check`，范围内零违例。
- 运行 `python3 "$MDF_ROOT/scripts/mdf.py" validate --repo "$REPO_ROOT"`，不新增 finding。
- 逐份对照改写前后的 diff，列出每条原有规则在新文本中的位置；缺失即回步骤 3。
- 提交使用中文 Conventional Commit，只含本次改写的文档。
- 报告改写文档清单、每份的主要结构变化与复核结果。
