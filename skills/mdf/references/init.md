# Init

它接入已有项目或调整现有 MDF 配置，将既有材料收敛到当前结构，
经`当前事实文档`的事实复核后使 `manifest` 进入 `ready`。新项目自动转入 bootstrap。

## 决策树

```text
┌──────────────────────────────────┐
│ 1 Check entry                    │
└────────────────┬─────────────────┘
                 ├──── 未就绪的新项目 ────> [内部执行 bootstrap 并返回]
                 ├──── 边界不明或异常 ────> [澄清或停止]
                 ▼ 通过
┌──────────────────────────────────┐
│ 2 Inventory                      │
└────────────────┬─────────────────┘
                 ▼ 通过
┌──────────────────────────────────┐
│ 3 Clarify layout                 │
└────────────────┬─────────────────┘
                 ▼ 通过
┌──────────────────────────────────┐
│ 4 Confirm plan                   │
└────────────────┬─────────────────┘
                 ├──── 分类或方案变化 ────> [回到对应澄清步骤]
                 ▼ 通过
┌──────────────────────────────────┐
│ 5 Initialize                     │
└────────────────┬─────────────────┘
                 ▼ 通过
┌──────────────────────────────────┐
│ 6 Audit facts                    │
└────────────────┬─────────────────┘
                 ├──── 审阅或校验未通过 ────> [修正、提交后重验]
                 ▼ 通过
┌──────────────────────────────────┐
│ 7 Enable workflows               │
└────────────────┬─────────────────┘
                 ▼ 结束；失败保留现场并报告
```

## 工作流（唯一执行契约）

完整读取 `references/initialization.md`、`references/common.md`、`references/clarify.md`
与 `references/repository-contract.md`。命中新仓库分流时完整读取并内部执行 `references/bootstrap.md`。

| # | 步骤 | 类型 | 做什么 | 证据 | 通过 → | 失败/缺失 → |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 入口 | 脚本 | [判定分流、准备 Git 并 doctor](#s1) | 项目状态与判定依据 | 新项目 bootstrap；否则 2 | 澄清或停止 |
| 2 | 盘点 | 约束 | [分类全部材料](#s2) | 分类清单 | 3 | 停止并澄清 |
| 3 | 布局 | 约束 | [决定去处与基线](#s3) | 逐项决定、命令 | 4 | 留在 3 澄清 |
| 4 | 方案 | 约束 | [展示初始化方案](#s4) | 用户明确确认 | 5 | 分类 2；其他 3 |
| 5 | 落地 | 脚本 | [scaffold 并归位](#s5) | 布局、归位核对表 | 6 | 保留现场，停止 |
| 6 | 审阅 | 约束 | [比较当前事实并 audit](#s6) | 事实复核、校验 | 7 | 修正并重验 |
| 7 | 就绪 | 脚本 | [校验并确认 ready](#s7) | 确认、校验、提交与分支 | 结束 | 保留现场，停止 |

## 术语与数据结构

### 执行约束

下列明细补充表中操作、证据与异常处理；步骤顺序和跳转只由上表规定。

<a id="s1"></a>

**入口**

先按 `initialization.md` 只读确认项目边界、新旧与 MDF 状态；未就绪且符合新仓库条件时，
说明依据后自动转入 bootstrap，不要求用户重新调用。已 ready 的空仓库仍在 init 调整配置。
其他项目按公共规则准备 Git 基础，再运行 doctor；不因普通目录、无提交或 dirty 一概拒绝。

验收：明确项目根、判定依据、Git 基础和 doctor；已初始化仅允许 initializing finding，或 ready 无 finding。

异常与交接：边界或改动归属不明时澄清，其他 finding 报告后停止。中间反馈继续本次流程，不重查入口。

<a id="s2"></a>

**盘点**

盘点全部顶层项目项并检查项目原有的全部文档，区分 MDF 固定项、治理/生态入口、实现、测试、 生成物与文档。

验收：分类清单。

异常与交接：停止并澄清。不得仅凭目录名或 README 保留；符合 CodeWiki 契约的 `docs/repowiki/`
留在原处且不纳入当前事实、ADR 或调研分类； 此步骤不做`事实复核`。

<a id="s3"></a>

**布局**

对每个非生态必需且非 MDF 固定的顶层目录，使用内部 clarify intent 决定去处或顶层例外；本地或外部调研材料归入
`context/research/`，已确认决策归入 `docs/adr/`，并从仓库证据收敛八项 `基线`、最近稳定版本与非空
`verification.commands`。每项为 id、kind、command；初始化 CLI 用重复的
`--verification-item '{"id":"check","kind":"custom","command":"git diff --check"}'` 传入。

验收：逐项决定与验证命令。

异常与交接：无法分类时一次只问一个问题。 仅含 `.gitkeep` 的占位目录按其未来职责迁移； 迁移目标已有实际内容时，
在同一方案中移除 `.gitkeep`，否则保留。业务实现目录和测试目录建议迁入 `src/<目录>`/`tests/<目录>`，
但不得在未经确认时迁移或删除。已接入 MDF 但暂无业务检查时可用 `git diff --check`；从未发布时最近稳定版本为 `none`。

<a id="s4"></a>

**方案**

形成`初始化方案`：路径、材料去处、保留内容、顶层允许清单、实现/测试目录、 拟补字段、基线、验证命令与预期
`validation`。

验收：用户明确确认。

异常与交接：材料分类有误时回到 2；去处、基线或验证命令需调整时回到 3。
移动/删除必须列出源、 目标和无信息损失理由，且不得覆盖既有内容。 不处理待实现意图；完成后用户可按输入形态显式
`$mdf intake` 或 `$mdf bug create` 或 `$mdf prp create`。配置调整必须再次显式调用 `$mdf init`。

<a id="s5"></a>

**落地**

执行 `init` 建立或更新完整 scaffold，保持 manifest `initializing`，传入核对后的完整配置与验证命令，
并只按方案归位/保留/排除原材料与顶层项。配置更新保留未要求修改的字段，续办核对已有产物，
不覆盖重建；完成材料后创建本地阶段提交，再审阅事实。

验收：固定布局、完整归位核对表、 `README.md`、`PROJECT.md`、`AGENTS.md` 与 `GLOSSARY.md` 各自符合`根文档职责`
且入口可达、没有未说明的遗留文件。

异常与交接：保留现场与 findings，不自动回退；停止并报告。
项目原有文档 与经确认迁移的顶层项目项只可按方案归位、保留或排除；保留 `AGENTS.md` 非 MDF 托管块；
完成当前事实文档、ADR、 `README.md`、`PROJECT.md` 与验证命令；在 `PROJECT.md`
记录仅含例外的顶层允许清单与目录约定。 方案调整仓库结构时，审视 `README.md` 的用户/维护入口、`PROJECT.md`
的维护手册与当前事实文档，消除重复。

<a id="s6"></a>

**审阅**

比较调用前后的 `GLOSSARY.md`、`docs/product/**` 与 `docs/system/**`，内部委托 `fact audit` 执行`全量审阅`。
先提交本次事实与证据作为可审阅基线；审阅发现问题时修正、提交并重验，不要求用户手动 commit 后重调。

验收：事实复核、diff 与 full validation；仅允许 `manifest.initializing` finding。

通过条件：审阅与校验通过后进入 7。异常与交接：未确认的语义问题继续澄清；其他 finding 修正后重验，
无法继续时保留现场并报告。提交不替代事实复核或用户确认。

<a id="s7"></a>

**就绪**

按 `initialization.md` 的公共完成规则展示当前事实复核、八项基线、验证命令和分支方案；
取得用户明确“结束初始化并启用正常工作流”确认后改 ready，校验、提交并核对本地 master/develop。

验收：事实审阅有效、full validation 零 finding、就绪结果已提交、本地分支可用。

异常与交接：事实发生变化则返回 6 补审，不复用过期结论；其他失败保留现场并报告，未通过不得宣称完成。
