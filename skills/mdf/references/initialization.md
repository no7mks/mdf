# 初始化公共规则

由 init、bootstrap 与 migrate 按各自阶段调用，不是用户 intent。完整读取
`references/common.md` 与 `references/repository-contract.md`。
调用方入口使用步骤 1；Git 准备使用 2；配置方案使用 3；材料落地及验收使用 4–5；
确认启用使用 6–8。决策树按调用方入口选用，不是单链；bootstrap/migrate 表写明
所调用的步骤号。
各段返回调用方；复用经核对仍有效的同次结果，不重复写入、审阅或确认。

## 决策树

```text
┌──────────────────────────────────┐
│ 1 Check boundary                 │
└────────────────┬─────────────────┘
                 │
                 ├──── 不明确 ────────────→ [澄清后返回 1]
                 ├──── 不符合调用条件 ────→ [按分流表返回调用方]
                 └──── 判定完成 ──────────→ [返回调用方]

步骤 2 由调用方按步骤号进入，不是步骤 1 的后续。

┌──────────────────────────────────┐
│ 2 Prepare Git                    │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [保留现场并报告]
                 └──── 通过 ─────────→ [返回调用方]

步骤 3 由调用方按步骤号进入，不是步骤 2 的后续。

┌──────────────────────────────────┐
│ 3 Configure                      │
└────────────────┬─────────────────┘
                 │
                 ├──── 配置或范围未确认 ────→ [返回调用方澄清]
                 └──── 通过 ────────────────→ [返回调用方落地]

步骤 4 由调用方按步骤号进入，不是步骤 3 的后续。

┌──────────────────────────────────┐
│ 4 Save baseline                  │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [保留现场并报告]
                 │
                 ▼ 阶段成果已提交
┌──────────────────────────────────┐
│ 5 Validate                       │
└────────────────┬─────────────────┘
                 │
                 ├──── 可修复的审阅或校验问题 ────→ 5 Validate
                 ├──── 无法继续 ──────────────────→ [保留现场并报告]
                 └──── 审阅及校验通过 ────────────→ [返回调用方]

步骤 6 由调用方按步骤号进入，不是步骤 5 的后续。

┌──────────────────────────────────┐
│ 6 Confirm activation             │
└────────────────┬─────────────────┘
                 │
                 ├──── 未确认 ────→ [保持 initializing，返回调用方]
                 │
                 ▼ 用户明确确认启用
┌──────────────────────────────────┐
│ 7 Enable                         │
└────────────────┬─────────────────┘
                 │
                 ├──── 事实变化 ────→ 5 Validate
                 ├──── 其他失败 ────→ [保留现场并报告]
                 │
                 ▼ ready 校验及提交通过
┌──────────────────────────────────┐
│ 8 Prepare branches               │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [保留现场并报告]
                 └──── 通过 ─────────→ [返回调用方完成]
```

## 工作流（唯一执行契约）

| # | 步骤 | 类型 | 做什么 | 证据 | 通过 → | 失败/缺失 → |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Check boundary | 约束 | 写入前核对边界、事实与状态 | 项目根与分流依据 | 返回调用方 | 不明回 1；否则按分流表返回 |
| 2 | Prepare Git | 脚本 | 运行 prepare-git；再提交基线；doctor | Git、允许的 findings | 返回调用方 | 保留现场并报告 |
| 3 | Configure | 约束 | 核对八项基线、版本、验证与实现根 | 配置、保留范围确认 | 返回调用方落地 | 返回调用方澄清 |
| 4 | Save baseline | 脚本 | 完成材料，保持 initializing 并复核提交 | 阶段提交、diff | 5 | 保留现场并报告 |
| 5 | Validate | 约束 | 按调用方审阅并全量校验 | 仅 initializing finding | 返回调用方 | 可修则 5；两轮后停 |
| 6 | Confirm activation | 约束 | 展示结果与方案并确认启用 | 用户明确确认 | 7 | 保持 initializing，返回调用方 |
| 7 | Enable | 脚本 | 写 ready，全量校验、提交后再次核验 | 零 finding、就绪提交 | 8 | 事实变化 5；其他保留现场停止 |
| 8 | Prepare branches | 脚本 | 按确认方案核对并补齐 master/develop | 本地分支及关系 | 返回调用方完成 | 保留现场并报告 |

## 术语与数据结构

### 项目边界与分流

<a id="s1"></a>

在任何写入前确定项目根；Git 化完成后该根即为 `REPO_ROOT`。读取起步材料并检查实际实现和运行证据。
不按仓库年龄、提交数量或文档数量判定。默认工程模板、README、需求草稿和选型材料
本身不代表已有业务；实际功能、接口、数据处理或已运行部署才构成既有项目事实。
部署配置可能只是模板，不能仅凭文件名判定；无法确定时先澄清。

先只读检查已有 `.mdf/manifest.yaml`：ready 表示已经接入 MDF，即使尚无业务也由
migrate 维护；initializing 不代表老仓库，应继续检查实际内容。不符合当前契约的既有
MDF 内容报告后停止，不推断历史语义。既有内容的校验在 Git 基础准备后执行。

| 调用 | 项目状态 | 行为 |
| --- | --- | --- |
| init | 未就绪且没有实际实现或运行事实 | 说明依据，内部转入 bootstrap，返回其结果 |
| init | 已有事实或已 ready | 内部转入 migrate，返回其结果 |
| bootstrap | 已有实际实现或运行事实 | 写入前报错、列证据并提示 `$mdf migrate` |
| bootstrap | 已 ready | 停止，配置调整提示 `$mdf migrate` |
| bootstrap | 未初始化或 initializing，且符合新仓库条件 | 建立起点或核对已有产物续办 |
| migrate | 未就绪且没有实际实现或运行事实 | 写入前报错、列证据并提示 `$mdf bootstrap` |
| migrate | 已有事实或已 ready | 继续 migrate |

### Git 基础

<a id="s2"></a>

入口允许普通目录和无提交的 Git 仓库。先用 `git rev-parse --show-toplevel` 检查边界；
位于其他仓库内部时先澄清，不直接嵌套 `git init`，不把父仓库默认为目标。
bootstrap 必须先通过新仓库判定，再执行本节，不能在拒绝老仓库前写入 `.git/`。
migrate 必须先通过已有事实或 ready 判定，再执行本节，不能在拒绝新仓库前写入 `.git/`。

确认纳管范围、忽略规则和分支调整方案后，先运行
`python3 "$MDF_ROOT/scripts/mdf.py" prepare-git --repo "$REPO_ROOT"`：
非 Git 目录初始化为 `master`，已是 Git 根则跳过，位于其他仓库内部则失败。
再由 Agent 完成身份与基线提交：

- 先提交应纳管的既有项目内容作为原始基线，再整理 MDF；空目录没有可提交内容时，
  不创建空提交，首个提交保存 MDF 起点。
- 已有 Git 历史保留。识别 staged、unstaged 和 untracked 改动，按公共规则确定归属，
  不通过提交全部改动换取 clean。没有提交身份时询问用户，不编造身份或修改全局配置。
- 新仓库在 master 上落地。既有 main、缺少 master、当前工作分支或远端默认分支
  不符合约定时，展示具体本地调整方案；不得重置已有分支、改写历史或强制对齐。
  涉及已有 master 冲突、远端默认分支或保护规则时确认方案后处理，不只提示用户自行改名。
- 不要求远端；保留已有远端，不自动创建托管仓库或推送。远端设置变更按已确认方案授权，
  无法完成时明确交接。开分支、切换和合并前按操作要求检查工作区。

Git 基础准备后运行 `doctor`。未初始化允许继续；已有有效 manifest 允许 ready，或仅
`manifest.initializing` finding；其他 finding 报告后停止。CLI init 仍要求 Git 根目录，
不负责语义判定、Git 化、提交或启用；init、bootstrap 与 migrate 共用该 CLI，
不新增 bootstrap 或 migrate CLI。

### 配置与完成

<a id="s3"></a>

从确认方案提供八项基线、最近稳定版本、`verification` 的五个入口（lint、build、
quick、smoke、full）、可选预算覆盖和 `implementation_roots`。从未发布时版本为
`none`；没有对应检查的入口可用 `git diff --check` 或 `true`。suite 语义与预算见
`delivery-contract.md`「验证 suite」。
不适用基线逐项给出真实理由，不用计划或占位事实页满足 documented。实现根可以为空目录；
单 module 默认使用 `src`，多 module 使用各 `<module>/src`；已有模板使用实际目录并在
PROJECT 说明，不为 bootstrap 重排模板。
`docs/system/testing/` 由 init CLI 写入起步页，按确认的验证配置填写当前规则与
quick、smoke、full 各一节，不把尚未采用的 kind 写成事实。

调用 `init` CLI 时传入完整配置：重复 `--baseline`、`--implementation-root`，
`--lint`、`--build`、`--quick`、`--smoke`、`--full`，以及可重复的
`--budget <suite>=<秒数>`。
更新时核对并保留未要求改变的配置，不依赖 CLI 默认值覆盖现有设置。已有根文档和
AGENTS 非 MDF 托管块必须保留；续办先检查 diff，只更新确认范围，不覆盖重建。
创建项目 `AGENTS.md` 时仅写标题与 MDF 托管区块；已有非托管内容仅以目标仓库实际文件为准。
不得将用户级、父目录或会话中继承的指令复制为项目规则，除非用户明确要求。
验收时对照写入前的项目文件，确认未新增未经要求的非托管规则。
已有项目文档保持原位；写入 `docs/` 下同名目录前核对内容和归属，不覆盖或自动接管。
`docs/README.md` 已存在时保留原文，仅按确认范围补充入口。
工作目录由 CLI 预建 `.gitkeep` 占位，文档入口直接列出各目录链接，不添加空目录状态或建目录提示。

<a id="s4"></a>

完成材料与配置，保持 initializing；清除本次模板占位说明，提交可验证的阶段成果。
核对提交范围及 diff；失败保留现场并报告。

<a id="s5"></a>

按调用方验收：migrate 完成事实审阅，bootstrap 核对起步材料；均执行 full validation。
bootstrap 不调用 fact audit，full validation 是确定性契约校验，不是事实审阅。
`manifest.state` 为 initializing 时仅允许 `manifest.initializing` finding；已是 ready
时须零 finding。其他 finding 修正、提交后重验；同一项两轮后无法继续。
通过后返回调用方验收步骤；调用方进入启用阶段时从 6 继续。无法继续则保留现场并报告。

<a id="s6"></a>

展示结果、八项基线、验证命令和分支方案，取得用户明确“结束初始化并启用正常工作流”确认。
未确认时保持 initializing 并返回调用方，不继续写 ready。

<a id="s7"></a>

将 manifest 改为 ready，执行 full validation，零 finding 后提交就绪结果；提交后再次核验。
事实发生变化时返回 5 补审补验，且步骤 5 按当前 `manifest.state` 验收；其他失败保留现场并报告，不宣称已完成。

<a id="s8"></a>

确保本地 master、develop 可用。新仓库从包含已提交就绪结果的 master 创建 develop；
已有分支保留，缺少 develop 时按确认方案从 master 创建，不重置、不强制对齐。
既有分支关系影响使用时报告具体问题并按确认方案处理，通过后才宣布完成。

语义确认不因提交而省略。失败保留现场和阶段提交，不宣称已完成；同次可修复继续，
同一项两轮为限。
暂停后的调用重新检查入口与已有成果，不因需要手动 commit 而要求重调。
