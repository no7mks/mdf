# Bug Create

## 决策树

```text
┌──────────────────────────────────┐
│ 1 Check entry                    │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [停止]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 2 Resolve bug                    │
└────────────────┬─────────────────┘
                 │
                 ├──── 需澄清或消歧 ────→ 2 Resolve bug
                 │
                 ▼ 输入唯一且完整
┌──────────────────────────────────┐
│ 3 Clarify                        │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [不写对象，停止]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 4 Confirm                        │
└────────────────┬─────────────────┘
                 │
                 ├──── 输入对象或来源变化 ────→ 2 Resolve bug
                 ├──── 既定对象需澄清 ────→ 3 Clarify
                 │
                 ▼ 用户确认 open
┌──────────────────────────────────┐
│ 5 Create bug                     │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [保留现场，停止]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 6 Report                         │
└────────────────┬─────────────────┘
                 │
                 ├──── 通过 ────→ [结束]
                 ├──── 失败/缺失 ────→ [停止]
```

## 工作流（唯一执行契约）

完整读取 `references/common.md`、`references/clarify.md`、 `references/repository-contract.md` 与
`references/object-contract.md`。

| # | 步骤 | 类型 | 做什么 | 证据 | 通过 → | 失败/缺失 → |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 入口 | 脚本 | [运行 doctor](#s1) | 允许正常流程 | 2 | 停止 |
| 2 | 对象 | 约束 | [确认单个 Bug](#s2) | 采用范围 | 3 | 等待澄清，2 |
| 3 | 澄清 | 约束 | [内部 clarify](#s3) | 必填事实 | 4 | 不写对象，停止 |
| 4 | 确认 | 约束 | [展示对象边界](#s4) | open 确认 | 5 | 来源变更 2；否则 3 |
| 5 | 创建 | 脚本 | [生成 ID 并写对象](#s5) | open Bug | 6 | 保留现场，停止 |
| 6 | 报告 | 约束 | [展示结果](#s6) | 会话摘要 | 结束 | 停止 |

## 术语与数据结构

### 执行约束

下列明细补充表中操作、证据与异常处理；步骤顺序和跳转只由上表规定。

<a id="s1"></a>

**入口**

解析 `REPO_ROOT` 并运行 `doctor`。

验收：`normal_workflows_allowed: true`。

异常与交接：manifest 未就绪时提示 `$mdf init`，其他 findings 报告后停止。

<a id="s2"></a>

**对象**

接收用户手动提供的单个 Bug 事实；一次只问一个问题，澄清范围、关键事实与取舍。
外部想法、 当前聊天上下文或外部文档必须显式调用 `$mdf intake`。

验收：确认的 Bug 与采用范围。

<a id="s3"></a>

**澄清**

使用内部 clarify intent 按轮次澄清观察到的行为、期望行为、复现步骤、影响、 所需回归证据、`found_in`
与 severity。

验收：完整必填事实。

异常与交接：必填事实仍无法确认时停止，不得写入任何对象。

<a id="s4"></a>

**确认**

展示 Bug、边界和排除范围。

验收：只有用户明确确认 open 才继续。

异常与交接：输入对象或来源变化时回到 2；既定对象的事实、范围或验收需澄清时回到 3。

<a id="s5"></a>

**创建**

为 Bug 提议并确认英文 ASCII kebab-case slug，使用 `make-id --type bug --slug` 生成 ID 与规范化文件名，
并以模板写入 `bugs/`，状态为 `open`。

验收：open Bug。

异常与交接：停止并保留现场。

<a id="s6"></a>

**报告**

展示 open Bug、确认事实和排除范围。

验收：会话摘要。

异常与交接：停止。
