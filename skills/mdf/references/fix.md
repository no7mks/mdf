# Fix

在当前 checkout 修复单个已有 Bug：澄清、确认有效红灯、修复并验证、标为
`fixed`。不切分支、不 start、不走交付主线、不 code-review、不 finish。

## 决策树

```text
┌──────────────────────────────────┐
│ 1 Check                          │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ─────────────→ [停止并报告]
                 ├──── fixed 且回归仍通过 ────→ 5 Record
                 │
                 ▼ open，或 fixed 但验证失败
┌──────────────────────────────────┐
│ 2 Clarify                        │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [不修复，停止]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 3 Reproduce                      │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [停止并报告]
                 │
                 ▼ 有效红灯已记录
┌──────────────────────────────────┐
│ 4 Repair                         │
└────────────────┬─────────────────┘
                 │
                 ├──── 未满三轮且下一步明确 ────→ 4 Repair
                 ├──── 目标不明或无法完成 ──────→ [停止并报告]
                 │
                 ▼ 修复完成且验证已通过
┌──────────────────────────────────┐
│ 5 Record                         │
└────────────────┬─────────────────┘
                 │
                 ├──── 通过 ─────────→ [结束]
                 └──── 失败/缺失 ────→ [停止并报告]
```

## 工作流（唯一执行契约）

读取 `references/common.md` 与 `references/object-contract.md`。
步骤 2 读取并内部执行 `references/clarify.md`。
CLI 使用 `python3 "$MDF_ROOT/scripts/mdf.py"`。
独立调用只推进当前 intent；不由 deliver 内部委托。

| # | 步骤 | 类型 | 做什么 | 证据 | 通过 → | 失败/缺失 → |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Check | 脚本 | 核对 ready、Bug 与 `--yolo` | doctor、list、参数 | open 或未过则 2；fixed 仍通过则 5 | 停止并报告 |
| 2 | Clarify | 约束 | 内部 clarify 修复范围与方案 | 共同理解 | 3 | 不修复，停止 |
| 3 | Reproduce | 约束 | 确认或编写该 Bug 的有效红灯测试 | 命令、退出状态、失败断言 | 4 | 停止并报告 |
| 4 | Repair | 约束 | 修复实现直到红灯转绿并验证 | 命令、退出状态、结果 | 5 | 未满三轮且下一步明确则 4；否则停止 |
| 5 | Record | 脚本 | 标为 `fixed`、校验并提交 | 对象、validate、提交 | 结束 | 停止并报告 |

## 术语与数据结构

### 范围与前置条件

解析 `REPO_ROOT` 并运行 `doctor`。验收：`normal_workflows_allowed: true`。
位置参数恰好一个 Bug ID；`--yolo` 可在其前或后。其他 `--` token 按入口未知
参数停止。缺 ID 或分不清时询问，不猜测，不创建 Bug。
运行 `list --repo "$REPO_ROOT" --type bug`（不限 status），按完整 ID 命中唯一
对象；也可用去掉 `bug-` 前缀的本体或 `path` 文件名 slug 各匹配一次。不匹配
title。不逐篇翻阅 `docs/bugs/`。
`closed` 或 `rejected` 停止。`open` 进入步骤 2。`fixed` 且回归验证仍通过则到
步骤 5 核对后结束，不重写；验证失败则进入步骤 2 续修。
不读取当前 Gitflow kind，不 start、不创建或切换 worktree。
写入落点按 `common.md`：master 不直接修改或提交。
不写 child Change，不填 `fixed_in`，不把对象标为 `closed`。

### 澄清

议题固定为「修复 <Bug ID>：根因范围、修复方案、回归证据与排除项」。
对照 Bug 的观察到的行为、期望行为、复现步骤、影响与所需回归证据。
默认取得用户对共同理解的明确确认。`--yolo` 时主 Agent 依据仓库证据与 Bug
正文自裁定共同理解，不向用户提问；死硬事实不可得仍停止。
不得削弱验收或把未确认范围写成已确认。`--yolo` 不跳过步骤 3 的红灯。

### 红灯

修复生产实现之前必须先有针对该 Bug 的有效红灯。本步不得改生产实现。
先按所需回归证据运行已有测试：能对应到 `manifest.verification.commands`
的 id 时，在仓库根运行该项 `command`；否则运行证据中的可执行命令。
已有测试以该缺陷的断言或期望失败时，记录命令、退出状态与失败断言，进入
步骤 4，不另造重复用例。
没有失败用例时，先编写能复现该缺陷的回归测试并运行；须得到针对该缺陷的
断言失败。导入错误、编译失败或环境故障不算有效红灯；测试本身有故障时先
修好测试再取红灯。新测试若通过，说明未复现，停止并报告，不改实现。
无法以断言失败复现时停止并报告。`--yolo` 不跳过本步，不得在无有效红灯时
进入修复。未记录有效红灯不得改生产实现。

### 修复与验证

只改该 Bug 范围内的实现、必要配置，以及步骤 3 已确认的回归测试。先让该
红灯测试转绿，再按所需回归证据重跑对应命令直到通过。记录命令、退出状态、
结果及对应证据项。
不按分支 kind 选择 suite，不因此跑全局 full，不调用 `project-verify` 或
`delivery verify` 冒充本 intent 完成。
不要求 feature 的 design/converge gate。
自检发现本阶段可修复的实现问题时原地修复并重验。可修复指同一失败未满三轮
且下一步修复动作明确；否则视为无法完成。
新增专用于该 Bug 的回归测试属于步骤 3 授权。修改已有测试的断言、预期、
fixture、跳过规则或任何验证门槛，需用户明确批准；`--yolo` 不代替该项批准。
目标不明、修复未完成、红灯未转绿或验证未通过时停止并报告，不把对象标为
`fixed`。

### 标记与提交

将 Bug `status` 改为 `fixed`，不得写 `fixed_in`，不得改为 `closed`。
运行 `validate --repo "$REPO_ROOT" --scope targeted`，回读对象并核对 `fixed`
与完整 diff。校验退出 0 且零 finding。
按 `common.md` 提交本次红灯测试、修复、回归验证与对象状态；不夹带无关改动。
摘要须区分已验证结论与未验证项，并写明红灯命令与转绿证据。

验收：有效红灯曾失败、现已通过、`fixed` Bug、校验零 finding、提交或明确
无新改动。二次验证与关闭对象由 `$mdf verify-fix` 与发版收口完成，不在本 intent
把状态改为 `closed`。
