# Heartbeat 状态确认

本契约要求跨 worktree 联调的 Agent 在每轮 heartbeat 时确认双方工作与等待依赖，避免互等。

## 触发与范围

每轮发出或收到 heartbeat，都由当前 Agent 通过既有 `send` 消息完成状态确认。

- 自动 heartbeat 只证明通道存活，不能证明对端 Agent 正在工作或双方已对齐。
- 本规则适用于通道打开后的各步骤，包括角色未定、计划未就绪、只传与收口等待。
- Agent 至少每 60 秒读取一次后台 Shell 输出；先处理状态询问，再继续当前步骤。
- 状态消息只用于同步，不代替 courtesy 的 ack、角色、计划、验收或收口确认。

## 每轮确认

Agent 用状态询问与状态回复，对齐本轮双方状态并确认下一步。

1. 发出或收到 heartbeat 后，主动 `send` 状态询问，写明本侧当前工作、等待依赖、下一步与负责人。
   - 同时询问对端上述信息；明确在等对端的哪个动作或结果，不能只写「等你」。
2. 收到状态询问立即 `send` 状态回复，报告本侧同样信息，并核对对方描述是否一致。
   - 状态回复直接回应本轮询问，不再次触发状态询问；双方同时询问时也先回复。
3. 收到回复后，确认双方当前工作、等待依赖与下一步已对齐；有歧义立即 `send` 澄清。
   - 未获对端状态时主动询问并继续读取本侧 poll，不能把自动 heartbeat 或旧回复当成本轮确认。
4. 双方都在等待时，主导方指出依赖关系，明确下一步、负责人和可观察结果，再向对端确认。
   - 能先推进的一侧立即执行并 `send` 告知；角色未定则先对齐角色，不能继续互相等就绪。
   - 双方都缺外部输入时，报告具体阻塞与所需输入；不把未解决的阻塞当成已恢复推进。

## 返回当前步骤

状态确认只解除误解与互等，不改变原步骤的通过条件或跨仓操作范围。

- 有可推进工作就执行；确需等待时，双方明确谁在做什么、本侧等待哪个结果，再继续 poll。
- 角色与计划阶段的状态 `send` 不作为业务确认；收口阶段也不作为测试报告或 `end`。
- 各侧仍只操作本仓、只读取本侧后台 poll，保持原 Goal 与进度，状态确认本身不触发 finish。
